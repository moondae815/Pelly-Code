# `pelly asp` (Classic ASP/VBScript 수정) 구현 계획 — 1단계 A1

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pelly asp <FILE> "<요청>"`이 `.asp`·`.inc` 파일 하나에서 VBScript `Function`·`Sub` 하나 또는 줄 범위 하나를 모델로 고치고, 실행 없이 할 수 있는 판정(바이트·인코딩·구조·안전·이름·규칙·`cscript` 컴파일·SP 존재)을 거쳐 사람이 승인하면 남긴다.

**Architecture:** Core에 `Asp/` 폴더를 새로 두고 손 해석기(VBScript 어휘·블록, ASP 페이지 구간), ASP 전용 파일 코덱(인코딩 판정·바이트 이어 붙이기), include 해석, 이름 색인, 구조·안전·이름 검사, SP 호출 찾기, `cscript` 컴파일 검사를 나눈다. 실행 흐름은 기존 `FsmOrchestrator`를 그대로 쓰고 `sql`처럼 ASP 전용 단계(`AspLocatePhase`·`AspSlicePhase`·`AspApplyPhase`·검증 단계 3개)를 `FsmOrchestratorFactory.CreateAsp`로 조립한다. `cs`·`sql` 경로의 동작은 바꾸지 않는다(additive 확장만, `FileGuard`의 코덱 주입은 기본값이 지금과 같다).

**Tech Stack:** .NET 10, System.IO.Abstractions, Spectre.Console.Cli, xUnit v3, Windows `cscript.exe`(Windows CI·현장), Ollama(로컬 예비 측정).

**Spec:** `docs/superpowers/specs/2026-11-04-pelly-asp-design.md` (§4.1–§4.7. §4.8 A2는 이 계획 밖)

## Global Constraints

- 작업 위치는 워크트리 `/Users/payletter/git-root/Pelly-Code-asp`(브랜치 `asp`). 셸 명령은 `cd /Users/payletter/git-root/Pelly-Code-asp && …`. 메인 체크아웃에서 빌드·테스트하지 않는다.
- 게이트: `dotnet build -warnaserror` 종료 0, `dotnet test` 실패 0(건너뜀은 SQL 서버·로컬 모델·Windows 전용만). Windows 전용 테스트는 `[WindowsFact]`(`tests/PellyCoder.Integration.Tests/Infrastructure/EnvFactAttributes.cs`)로, CI `windows-integration`이 `--fail-skips on`으로 돌린다 — `cscript`가 없으면 CI가 실패해야 한다.
- 편집 영역 밖은 **원본 바이트 그대로**(줄 끝이 섞인 파일 포함). 인코딩 판정 순서(그대로): BOM → `<%@ … CodePage=N %>`(65001 → UTF-8, 949 → CP949, 그 밖 → 종료 4) → ASCII 아닌 바이트가 있으면 엄격한 UTF-8 아니면 CP949 → 순수 ASCII면 `asp.encoding`(기본 `cp949`). 정한 인코딩으로 엄격하게 못 읽으면 종료 4. UTF-16 BOM 파일은 종료 4(「UTF-16 ASP 파일은 지원하지 않습니다」).
- 공용 `TextDecoding`·`TextFileCodec`의 동작은 바꾸지 않는다.
- 모든 검사는 원본 기준선 대비 **새로 생긴 것만**, 위치가 아닌 내용(코드+문구 또는 규칙+정규화 문장)의 개수로 센다. 메시지에 줄 번호를 넣지 않는다(줄 번호는 별도 필드).
- 대상 확장자 기본 `.asp`, `.inc`(대소문자 무시). `global.asa`는 확장자 설정과 상관없이 거부(종료 3). 서버 JScript는 거부(종료 3, `AspUnsupportedLanguage`).
- 프로시저 대상의 이름·매개변수 변경은 요청과 상관없이 거부(재시도 피드백).
- 안전 검사 규칙 ID(그대로): `ShellObject`(`WScript.Shell`, `Shell.Application`, `WScript.Network`, 원본에 없을 때의 `Scripting.FileSystemObject` — `CreateObject`·`Server.CreateObject`의 문자열 인수), `DynamicCode`(`Execute`, `ExecuteGlobal`, `Eval`), `OnErrorResumeNext`, `SqlConcatRequest`.
- SQL 문자열 판정 단어(단어 경계, 대소문자 무시): `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `EXEC`, `EXECUTE`, `MERGE`. 기본 허용 감싸기: `CLng`, `CInt`, `CDbl`, `CBool`, `CDate`, `Replace(x, "'", "''")`(두 번째·세 번째 인수가 정확히 그 문자열 리터럴), 그리고 `asp.sqlSanitizers`.
- include: 깊이 5, 파일 40개. `virtual=`은 `asp.siteRoot`(없으면 작업 공간 루트) 기준.
- `cscript` 인수(그대로): `//Nologo`, `//T:10`, `//E:vbscript`, `<임시 .vbs 경로>`. `//B`는 쓰지 않는다. 프로세스 시간 제한 30초. 임시 `.vbs`는 `.pelly/runs/<runId>/asp-compile-<n>.vbs`, UTF-16 LE + BOM.
- 컴파일 오류 줄 형식: `<경로>(<줄>, <열>) Microsoft VBScript <종류>: <내용>`. 종류는 `compilation error`(영어)와 `컴파일 오류`(한국어)를 알아보고, 그 밖의 종류(`runtime error`, `런타임 오류`)는 컴파일 검사에서 무시한다. 출력 바이트는 `TextDecoding.Decode`(UTF-8 → CP949)로 읽는다. 오류 줄이 마지막 줄 다음이면 마지막 줄로 붙인다.
- 개발 DB(`sql.connectionString`)만 쓴다. `sql.production`은 ASP에서 쓰지 않는다.
- 새 실패 유형 문자열(그대로): `AspStructureErrors`, `AspUnknownNames`, `AspCompileErrors`, `AspSafetyRejected`, `AspEncoding`, `AspSpNotFound`, `AspUnsupportedLanguage`, `AspUnsupportedFile`.
- 프롬프트 버전 문자열 `asp-v1`. 예산은 `budget.*` 그대로.
- 검토 고정 문구(그대로): 「ASP는 실행해서 확인하지 않았습니다. 화면에서 직접 확인하십시오.」
- 종료 코드는 기존과 같다(0 성공, 1 검증 실패, 2 거부·중단, 3 대상 못 찾음·모호, 4 환경, 5 안전 가드).
- `HttpClient` 생성은 `src/PellyCoder.Cli/Composition.cs`에만(`NetworkPolicyTests`). 코퍼스·문서에 사내 값(서버 주소·사용자 이름)을 쓰지 않는다(공개 저장소).
- 사용자 문구 한국어, 코드 식별자·주석 영어. 커밋 끝 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. push하지 않는다.

## Review Focus

1. **HTML을 사이에 두고 이어지는 블록**(`<% If a Then %> … <% Else %> … <% End If %>`)을 줄 범위로 일부만 고침 — 범위 밖에서 열린 블록 때문에 구조 오류로 보지 않는다(파일 전체로 셈, 기준선 대비). 테스트: Task 1 `Blocks_SpanHtmlSegments`, Task 8 `LinesTarget_InsideHtmlSplitIf_Passes`.
2. **CP949 파일, 줄 끝 섞임, 끝 줄바꿈 없음**에서 범위 안 한 줄만 바꿈 — 범위 밖 바이트가 원본과 같다. 테스트: Task 2 `Encode_MixedNewlines_OutsideBytesIdentical`, Task 12 `Cp949MixedFile_Approved_OutsideBytesIdentical`.
3. **원본에 이미 `Request` 연결 SQL·정의 못 찾는 이름·짝 안 맞는 태그가 가득한 페이지** — 새로 생긴 것만 막고 나머지는 통과. 테스트: Task 6 `Safety_ExistingConcat_NotCounted`, Task 7 `Names_ExistingUnknown_NotCounted`, Task 5 `Structure_ExistingProblems_NotCounted`.
4. **`Option Explicit` 페이지에서 모델이 새 변수를 `Dim` 없이 씀 / 없는 함수를 지어냄** — 이름 검사가 줄과 이름을 피드백한다. 테스트: Task 7 `Names_OptionExplicit_UndeclaredVariable_Error`, `Names_InventedFunction_Error`.
5. **Mac(cscript 없음)·SQL 미설정에서 실행** — 멈추지 않고 진행하되 검토와 `summary.json`에 「건너뜀」이 보인다. 테스트: Task 9 `Compile_NotWindows_Skipped`, Task 11 `Review_ShowsSkippedChecksAndBanner`.
