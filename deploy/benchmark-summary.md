# 벤치마크 결과 요약 (pelly 0.9.0)

반입 전에 개발 PC에서 잰 M3b 최종 결과입니다. 폐쇄망 서버에서 다시 잰 값이 아닙니다.

## 조건

| 항목 | 값 |
| :--- | :--- |
| 날짜 | 2026-10-18 |
| 측정 환경 | 개발 PC (macOS arm64), .NET SDK 10.0.302, Ollama 0.40.0 |
| 모델 | `qwen3.6:35b-a3b-coding-nvfp4` (safetensors `nvfp4`. 현장 서버의 GGUF `Q4_K_M`과 양자화가 다릅니다. 이 모델의 digest는 `version-record.json`에 있고, 현장 모델의 GGUF SHA-256은 M4에서 기록합니다) |
| 작업 | 50건 (cs-legacy 18 · cs-modern 12 · sql 20) × 3회 반복 |
| 설정 | 제품 기본값 (프롬프트 `cs-v2`·`sql-v1`, `llm.thinkMode = retry`, `budget.think = 512`) |

* Legacy(.NET Framework) 작업 18건은 Windows가 아닌 PC에서 쟀습니다. 그래서 빌드 검증 없이 패치 적용·모양 검사까지만 판정했습니다.
* SQL 작업은 실행 전후 DB 객체를 비교했고 바뀐 것이 없었습니다.
* 측정한 실행 파일은 버전 `0.1.0`으로 빌드됐습니다(실행 기록의 `pellyVersion`). 제품 코드는 커밋 `19bccc1`과 같습니다(docs/m3b-baseline.md). 그 뒤 반입본 버전을 `0.9.0`으로 올렸습니다. 이후 바뀐 제품 코드는 패키지·자체 점검, `--test` 판정, 명령줄 인자 검사뿐이고 벤치마크가 쓰는 수정 경로(프롬프트·샘플링·검증)는 같습니다. 0.9.0 실행 파일로 다시 재지는 않았습니다.

## 튜닝 결과

미리 정한 후보 3개를 같은 조건(50건 × 3회)으로 쟀습니다. **채택한 후보는 없습니다.** 기본값과 프롬프트는 그대로이고, 위 KPI가 최종 값입니다.

채택 규칙: 평균 성공이 1.0건 이상 늘고, 어떤 범주도 0.5건 넘게 줄지 않고, 위반이 0건이고, 시간 중위값이 1.5배 이하일 것.

| 기준선 | — | 47.67 | 1.90초 | 0·0·0 | — |
| think 768 | `budget.think` 512 → 768 | 47.67 | 1.93초 | 0·0·0 | 거절 (+0.00) |
