# PellyCodeMcpServer 효과 측정 (C# 2026-11-17, SQL 2026-11-18)

OpenCode에 PellyCodeMcpServer를 붙였을 때 결과가 달라지는지 같은 작업 묶음으로 비교했다.
실행 방법은 `eval/opencode/README.md`를 따른다.

## 조건

- 에이전트: OpenCode 1.18.25, 모델 `qwen3.6:35b-a3b-q4_K_M` (Ollama 0.40.0, macOS)
- 작업: 코퍼스 C# 30건 (legacy 18, modern 12), 변형마다 1회
- 변형
  - **base** — MCP 서버 없음
  - **mcp** — `pelly_impact`·`pelly_verify` 등록 (`opencode.mcp.json`)
  - **mcp-agents** — mcp + `eval/opencode/overlay/AGENTS.md` (고친 뒤 `pelly_verify`를 부르라는 안내)
- macOS라 legacy 18건은 빌드 판정 없이 패치 적용·모양 검사까지만 판정했다 (설계 §10.6).

## 읽는 법

- **도구 등록만으로는 거의 쓰이지 않는다.** 등록만 한 mcp 변형은 30건 중 4건에서만 `pelly_verify`를 불렀다. AGENTS.md로 안내하면 26건으로 늘었다. 현장에서는 AGENTS.md 안내를 함께 넣는 것이 전제다 (`deploy/mcp-server.md`).
- **정확도 차이는 측정되지 않았다.** 25/25/24는 한 번씩 돌린 결과의 흔들림 범위 안이다. 빌드가 깨진 채 끝난 작업 수도 세 변형 모두 1건으로 같다.
- **시간 부담은 작다.** 중위값이 1~3초 늘었다. 기준 빌드를 미리 해 두는 설계 덕에 `pelly_verify` 한 번이 작업 시간을 크게 늘리지 않았다.
- 이번 작업 묶음에서는 모델이 빌드를 깨는 경우 자체가 드물어(30건 중 1건) 검증 도구가 실패를 막을 기회가 적었다. 효과를 보려면 빌드가 자주 깨지는 큰 변경이나 SQL·웹 작업으로 다시 재야 한다.

## SQL 결과 (2026-11-18)

같은 조건으로 코퍼스 SQL 20건을 변형마다 1회 돌렸다. 개발 DB 연결은 환경 변수로 주었다.

| 변형 | 성공 | `pelly_verify`를 부른 작업 | 시간 중위값 / P90 |
| :--- | ---: | ---: | :--- |
| base | 19/20 | 0 | 56.4초 / 104.5초 |
| mcp | 20/20 | 0 | 53.4초 / 65.9초 |
| mcp-agents | 20/20 | 18 | 58.0초 / 89.7초 |

- base의 실패 1건(sql-014)은 대상 파일을 바꾸지 않은 경우다. mcp 변형은 도구를 한 번도 부르지 않았으므로 이 차이는 도구 효과가 아니라 실행 간 흔들림이다.
- C#과 같은 모습이다. 등록만으로는 부르지 않고(0/20), AGENTS.md 안내가 있으면 18/20에서 부른다. 독립 검증 위반은 세 변형 모두 0건이다.
- SQL 작업은 모델 혼자서도 거의 다 맞혀(19~20/20), 이 묶음으로는 검증 도구의 효과를 가를 수 없다.

## 한계

- 변형마다 1회 실행이다. 작업 1~2건 차이는 의미 있는 차이로 보지 않는다.
- 모델 digest가 현장(`07d35212591f`)과 다르다 (측정 `b52ca43760e9`).
- OpenCode 로그에는 `pelly_verify`가 돌려준 본문이 남지 않아, 도구가 오류를 보고했는지와 모델이 그에 따라 고쳤는지는 확인하지 못했다.
- macOS에서는 legacy 빌드를 판정하지 않았다. Windows 현장에서 다시 재야 legacy 쪽 효과를 알 수 있다.
- SQL 측정에서도 도구가 돌려준 본문은 로그에 남지 않아, `pelly_verify`가 실제로 SQL을 컴파일했는지는 확인하지 못했다.
