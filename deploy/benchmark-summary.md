# 벤치마크 결과 요약 (pelly 0.9.1)

반입 전에 개발 PC에서 잰 결과입니다. 모델은 현장 서버와 **같은 파일**이지만, 폐쇄망 서버에서 다시 잰 값은 아닙니다.

## 조건

| 항목 | 값 |
| :--- | :--- |
| 날짜 | 2026-10-20 |
| 측정 환경 | 개발 PC (macOS arm64), .NET SDK 10.0.302, Ollama 0.40.0 (llama.cpp, GPU) |
| 모델 | `qwen3.6:35b` (GGUF `Q4_K_M`). 식별 정보는 `version-record.json`에 있습니다 |
| 작업 | 50건 (cs-legacy 18 · cs-modern 12 · sql 20) × 3회 반복, 두 번 측정 |
| 설정 | 제품 기본값 (프롬프트 `cs-v2`·`sql-v1`, `llm.thinkMode = retry`, `budget.think = 512`) |

* **같은 파일인지 확인:** 서버에서 `ollama list`를 실행해 `qwen3.6:35b`의 ID가 `a7eb95c53bcf`인지 보십시오.
  * 같으면 측정과 같은 모델 파일입니다. GGUF SHA-256은 `version-record.json`의 `modelGgufSha256`입니다.
  * 다르면 다른 시점에 받은 파일이라, 아래 값은 참고치로만 쓰십시오.
* Legacy(.NET Framework) 작업 18건은 Windows가 아닌 PC에서 쟀습니다. 그래서 빌드 검증 없이 패치 적용·모양 검사까지만 판정했습니다.
* SQL 작업은 실행 전후 DB 객체를 비교했고 바뀐 것이 없었습니다.
* 측정한 실행 파일은 반입본과 같은 버전 `0.9.1`입니다.

## 튜닝 결과 (M3b, `nvfp4` 파일로 측정)

미리 정한 후보 3개를 같은 조건(50건 × 3회)으로 쟀습니다. **채택한 후보는 없습니다.** 기본값과 프롬프트는 그대로입니다.

* 이 튜닝은 이전 모델 파일로 쟀습니다. 현장 파일에서 튜닝 후보를 다시 재는 일은 현장 절차(`field-guide.md` 8절)가 맡습니다.
* 채택 규칙: 평균 성공이 1.0건 이상 늘고, 어떤 범주도 0.5건 넘게 줄지 않고, 위반이 0건이고, 시간 중위값이 1.5배 이하일 것.

| 후보 | 바꾼 조건 | 평균 성공 | 시간 중위 | 위반 | 판정 |
| :--- | :--- | ---: | ---: | :--- | :--- |
| 기준선 (`nvfp4`) | — | 47.67 | 1.90초 | 0·0·0 | — |
| think 768 | `budget.think` 512 → 768 | 47.67 | 1.93초 | 0·0·0 | 거절 (+0.00) |
| code 샘플링 | `temperature` 0.1 → 0.2, `topP` 0.9 → 0.95 | 47.00 | 1.85초 | 0·0·0 | 거절 (−0.67, cs-modern −0.67) |
| 예시 보강 | 예시에 DTO 구간 추가 | 47.33 | 1.94초 | 0·0·0 | 거절 (−0.33) |

* 남은 실패는 1차 시도에서 성공으로 끝나므로 교정 경로(think·피드백)가 개입하지 않습니다. 후보들이 닿지 못한 이유입니다.
