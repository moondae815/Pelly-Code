# `pelly js`·`pelly css` W2 (페이지 안 `<script>`·`<style>`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pelly js`·`pelly css`가 ASP·HTML 페이지 안의 클라이언트 `<script>`·`<style>` 블록을 W1 판정으로 고친다. `pelly asp`가 블록에 걸친 편집에 JS·CSS 판정을 더한다. `pelly edit`이 줄 위치로 명령을 고른다.

**Architecture:**
- `AspPage`에 구간 목록과 겹치는 **클라이언트 블록 목록**을 더한다.
- 블록마다 페이지와 줄 수가 같은 **보기 텍스트**(블록 내용만 남기고 나머지는 공백, `<%= %>`는 자리 표시)를 만든다. 그래서 W1의 해석기·검사 API를 바꾸지 않고 그 결과 줄 번호를 페이지 줄 번호로 그대로 쓴다.
- `WebRunState`는 페이지 실행에서 `OriginalText`로 원본 보기 텍스트를 들고, `ViewOf(pageText)`로 수정본 보기 텍스트를 만든다. W1 단계들은 파일 텍스트 대신 이것을 판정한다.
- 쓰기는 ASP 코덱(바이트 이어 붙이기)으로 한다.

**Tech Stack:** .NET 10, C#, Acornima 1.9.0(이미 있음), xUnit, System.IO.Abstractions(MockFileSystem).

**Spec:** `docs/superpowers/specs/2026-11-06-pelly-web-w2-design.md`. 이어 받는 설계는 `docs/superpowers/specs/2026-11-04-pelly-js-css-design.md`(W1)·`2026-11-04-pelly-asp-design.md`(A1)다.

## Global Constraints

- 작업 위치는 워크트리 `~/git-root/Pelly-Code-w2`(브랜치 `w2`)다.
  - 명령은 `cd ~/git-root/Pelly-Code-w2 && …`로 실행한다.
  - push하지 않는다. 서브에이전트가 또 서브에이전트를 띄우지 않는다.
- 게이트: `dotnet build -warnaserror` 종료 0, `dotnet test` 실패 0. 건너뜀은 SQL 서버·Ollama·Windows 전용만 허용한다.
- 이 머신은 macOS다. 경로 테스트는 Windows에서도 맞게 쓴다(MockFileSystem 전체 경로, `Path.Combine`).
- 커밋 메시지는 영어 conventional로 쓰고, 끝에 빈 줄 + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`을 붙인다. 태스크마다 커밋 하나 이상이다.
- 사용자 문구·문서는 한국어, 모델 피드백은 영어다(W1과 같음). 한국어 메시지는 숫자 바로 뒤에 조사를 붙이지 않는다.
- 페이지 = `options.Asp.Extensions`(기본 `.asp`·`.inc`) + `.htm`·`.html`, 대소문자 무시(설계 §2-1).
- **A1·W1 동작은 바뀌지 않는다.**
  - `.js`·`.css` 파일 실행과 블록이 없는 범위의 `pelly asp` 실행은 기존 테스트가 그대로 통과해야 한다.
  - 예외는 설계가 정한 두 곳뿐이다. W1 이름 검사가 페이지 블록 선언을 아는 이름으로 치고(설계 §4.6), `pelly asp`의 판정 표에 행이 더해진다(설계 §4.5).
- 새 실패 유형 문자열은 `WebBlockChanged`, `WebServerCodeChanged`, `WebOutsideBlock`(설계 §4.9)이다.
- ASP 판정 표 새 행 이름은 `JsSyntax`, `JsLevel`, `JsSafety`, `CssSyntax`, `CssSafety`, `JsNames`, `JsApi`(설계 §4.5)다.
- 프롬프트 판 이름은 `js-page-v1`, `css-page-v1`, `asp-v2`(설계 §4.5·§4.7)다.
- 사내 값(서버 주소·사용자 이름)을 쓰지 않는다(공개 저장소).

## Review Focus

1. **따옴표가 든 `<%= %>`가 JS 문자열 안에 있는 경우**(`var s = '<%= Replace(v, "'", "\'") %>';`). 자리 표시가 서버 구간 전체를 덮어야 보기 텍스트가 정상 JS가 된다. → Task 2 테스트 `Output_with_quotes_inside_js_string_parses`.
2. **같은 페이지에 `<% If %>`가 섞인 블록과 깨끗한 블록이 함께 있는 경우.** 깨끗한 블록을 고치면 그 블록은 정상 문법 판정을 받아야 한다(블록마다 따로). → Task 4 테스트 `Clean_block_is_parsed_normally_when_another_block_has_statements`.
3. **CRLF·CP949 페이지.** 블록 안을 고친 뒤 블록 밖 바이트가 원본과 같아야 한다. → Task 6 테스트 `Page_edit_keeps_bytes_outside_the_block_cp949_crlf`.
4. **모델이 문자열에 `"</script>"`를 넣는 경우.** `WebBlockChanged`로 재시도하고, 피드백에 `<\/script>`를 적어야 한다. → Task 6 테스트 `Closing_tag_in_string_is_WebBlockChanged_with_hint`.
5. **`.inc`를 부르는 페이지가 없거나, 부르는 페이지들의 jQuery 버전이 다른 경우.** 없으면 아래쪽만 보고, 다르면 가장 낮은 버전을 쓴다. → Task 7 테스트 `Inc_without_parents_looks_down_only`, `Inc_parents_with_different_jquery_take_lowest`.

  - `Unclosed_block`: `<script>\nvar a;` → `Closed=false`.
  - `Case_insensitive_tags`: `<SCRIPT TYPE="TEXT/JAVASCRIPT">a</Script>` → 블록.
  - `Lines_are_page_lines`: 3줄 HTML 뒤 4–6줄 블록 → OpenLine 4, ContentStartLine 4(같은 줄 `>` 뒤에 내용이 시작하면 4, 내용이 다음 줄부터면 5), CloseLine 6.
  - `ClientBlockAt_content_lines_only`: 여는 태그만 있는 줄(내용 없음)은 null, 내용 줄은 (블록, 0).

  - `--line N` → 그 줄의 블록 종류
  - `--lines A-B` → 범위 전체가 블록 하나의 내용 안이면 그 종류, 아니면 asp
  - 지정 없음 → `.htm`·`.html`이면 js, 아니면 asp
  - `.htm`·`.html`이 asp로 가야 하면 종료 4: 「.htm 파일의 HTML 부분은 고치지 않습니다」
- 안내 문구: `{파일} {N}줄 → <script> 블록이라 pelly js로 실행합니다`(`<style>`이면 css)를 쓴다. 블록 판정이 없는 경우에는 기존 `{ext} 파일 → pelly {cmd}로 실행합니다` 문구를 쓴다.
