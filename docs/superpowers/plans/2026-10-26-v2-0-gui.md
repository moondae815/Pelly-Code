# V2-0 GUI 승인 창 (`pelly ui`) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pelly ui cs|sql <파일> …`로 Avalonia 창을 띄워 요청 입력·진행 표시·diff 승인을 하고, 실행은 기존 FSM을 그대로 쓴다.

**Architecture:** Core의 `IUserInteraction`에 기본 구현이 있는 메서드 둘(`ApproveAsync`, `ShowWaiting`)을 더해 GUI가 승인/경고와 대기 갱신을 구분하게 한다. 새 프로젝트 `src/PellyCoder.Ui`가 Avalonia에 기대지 않는 상태 기계(`UiSession`)·`GuiUserInteraction`과 Avalonia 창(`MainWindow`, `UiHost`)을 가진다. `PellyCoder.Cli`가 `ui` 분기 명령을 등록하고, 인수 검증을 `cs`·`sql`과 함께 쓰며, 실행마다 GUI용 `IRunner`를 조립한다.

**Tech Stack:** .NET 10, Avalonia 12.1.4 (`Avalonia`, `Avalonia.Desktop`, `Avalonia.Themes.Fluent`, 테스트 `Avalonia.Headless.XUnit`), xUnit v3 (`xunit.v3.mtp-v2`), Spectre.Console.Cli, DiffPlex.

**Spec:** `docs/superpowers/specs/2026-10-26-v2-0-gui-design.md`

```csharp
public interface IUiDispatcher { void Post(Action action); }   // UI 스레드로 보냄. 테스트는 즉시 실행

public enum SessionState { Idle, Running, AwaitingAnswer, Cancelling, Finished, Invalid }

public delegate Task<int> RunFunc(string request, IUserInteraction ui, CancellationToken ct);

public enum QuestionKind { Approve, Confirm, Select }
public sealed record PendingQuestion(QuestionKind Kind, string Message, IReadOnlyList<string> Choices);
// Choices: Select일 때 표시 문구, 그 밖에는 빈 목록

public sealed record StatusLine(RunPhase? Phase, int Attempt, string Text, StatusLineKind Kind);
public enum StatusLineKind { Status, Waiting, Warning, Error, Result }

public sealed class GuiUserInteraction : IUserInteraction
{
    public GuiUserInteraction(IUiDispatcher dispatcher);
    public ObservableCollection<StatusLine> Lines { get; }          // UI 스레드에서만 바뀜
    public IReadOnlyList<(char Kind, string Text)>? DiffLines { get; } // 마지막 ShowDiff (Core DiffRenderer 결과)
    public string? DiffPath { get; }
    public PendingQuestion? Question { get; }
    public string? RunSummaryText { get; }                          // ShowRunSummary를 여러 줄 텍스트로
    public event Action? Changed;                                   // UI 스레드에서 발생
    public void Answer(int choice);   // Approve/Confirm: 1=예, 0=아니오. Select: 고른 인덱스
    public void ClearForNewRun();     // 줄·diff·질문·요약 비움
}

public sealed class UiSession
{
    public UiSession(RunFunc run, GuiUserInteraction ui, IReadOnlyList<string> argumentErrors, CancellationToken shutdown);
    public SessionState State { get; }
    public string Request { get; set; }
    public bool CanRun { get; }             // State is Idle or Finished && Request가 공백 아님
    public int ExitCode { get; }            // 마지막 실행 코드. 실행 전 2. Invalid면 4
    public IReadOnlyList<string> ArgumentErrors { get; }
    public Task RunAsync();                 // CanRun일 때만. 끝나면 Finished
    public void Cancel();                   // Running/AwaitingAnswer → Cancelling
    public bool RequestClose();             // 지금 닫아도 되면 true. 아니면 취소를 걸고 false, 실행이 끝나면 CloseReady 발생
    public event Action? Changed;
    public event Action? CloseReady;
}
```

동작 규칙(설계 §3·§5):
- `ShowStatus`는 새 `Status` 줄을 더한다. `ShowWaiting`은 마지막 줄이 `Waiting`이면 그 줄을 바꾸고, 아니면 새 `Waiting` 줄을 더한다. `Warn`은 `Warning` 줄.
- `ApproveAsync` → `QuestionKind.Approve`, `ConfirmAsync` → `Confirm`, `SelectAsync` → `Select`. 질문은 `TaskCompletionSource`로 기다리고 `ct`가 취소되면 `OperationCanceledException`으로 끝난다. 질문이 떠 있는 동안 또 질문이 오면 `InvalidOperationException`.
- `UiSession`은 실행마다 `CancellationTokenSource.CreateLinkedTokenSource(shutdown)`를 새로 만든다. `RunFunc`가 `OperationCanceledException`을 던지면 종료 2, 다른 예외는 `Error` 줄(예외 메시지)과 종료 4. 끝나면 `Result` 줄: `$"종료 코드 {code}: {ExitCodeText.Describe(code)}"`.
- `argumentErrors`가 비어 있지 않으면 시작 상태가 `Invalid`, 오류마다 `Error` 줄, `CanRun` 거짓, `ExitCode` 4, `RequestClose()`는 늘 참.
- 질문 대기(`AwaitingAnswer`) 중 `RequestClose()`는 답을 「아니오」로 주지 않고 **취소**를 건다(거부와 결과가 같은 종료 2이고 롤백 경로가 하나로 모인다).
